### GOAL 1 (ISO Load and Weather Pipeline)

Required libraries: pandas, matplotlib

The pipeline cleans, imputes, merges, and plots hourly ISO load and weather data. It currently supports NYISO and CAISO data, as this was the data used for this project. 


The Pipeline: 
- Reads load and weather data from CSV files, ZIP files, folders, or file lists
- Standardizes load schemas for NYISO and CAISO
- Standardizes weather schemas for NYISO and CAISO
- Summarizes missing values and duplicate hourly records
- Imputes missing hourly load using the same hour from the time amount missing but earlier
- Merges load and weather on `Name` + `Hour Start`
- Writes a merged CSV of standardized values
- Generates a load vs. temperature plot


To utilize the pipeline, use the function run_iso_pipeline() which takes in a string of the ISO you want (ie. NYISO), load_csv_path (of the load file from the ISO), weather_csv_path (of the weather file from the National Weather Service), final_output_csv_path (the file path you want the output to go to), plot_output_path (an optional path for the output plot if you want to save it), and temp_col (an optional input for the column you want to plot with the load data for that year in the plots generated by the pipeline).


The pipeline supports inputs from a single .CSV file, a single .ZIP file of CSVs, or a directory containing .CSV or .ZIP files. ZIP files are supported for cases like NYISO daily archives that contain CSVs inside.


For NYISO data, the expected columns include ‘Hour Start’ or ‘Time Stamp’, ‘Name’, and ‘Hourly Avg Load’ or ‘Load’. Raw NYISO files with ‘Time Stamp’ and ‘Load’ are normalized automatically. For CAISO data, expected columns are either ‘Hour Start’ or ‘Date’ and ‘HR’, and at least one of ‘PGE’, ‘SCE’, ‘SDGE’, ‘VEA’, and ‘CAISO Total’ or ‘CAISO’. CAISO utility columns are reshaped from wide to long format. Weather data must contain ‘Hour Start’ and either ‘Name’ or ‘Zone’. For CAISO, the weather zone names are mapped to utilities: “NP15”: “PGE”, “SP15”: “SCE”, “SP15”: “SDGE”,  and “ZP26”:“VEA”.


The pipeline outputs the resulting data .CSV files and a plot image, but also a dictionary with summary information of the pipeline actions. The dictionary contains: 
- ISO name
- input files used
- raw row counts
- merged row counts
- missing-data summaries before and after imputation
- output file paths
- matplotlib figure object


### GOAL 2 (Forecasting Pipeline)
Required Libraries: pandas, numpy, scikit-learn, lightgbm, sktime
The pipeline builds and evaluates an hourly electricity demand forecasting model for a selected ISO load zone using historical load and weather data. It currently supports forecasting for zones within NYISO and CAISO, as these were the ISOs used in this project.


The Pipeline:
- Filters the merged dataset for a selected load zone
- Converts timestamps to hourly datetime format and sorts the data chronologically
- Resamples the data to hourly frequency
- Defines the target variable as hourly average load
- Builds cyclical time-based features for hour of day, day of week, and day of year
- Adds weather variables, including temperature, relative humidity, precipitation, windspeed, and dewpoint when available
- Splits the data into a training window and a 168-hour test window
- Builds a recursive forecasting pipeline using sktime and LGBMregressor
- Generates one-week ahead hourly load predictions
- Computes daily peak RMSE and MAPE


To utilize the pipeline, use the function build_sktime_LGBM_model() which takes in df (the merged load and weather dataframe), zone_name (the load zone to forecast, such as “CAPITL” or “PGE”), start_date (the first timestamp of the 168-hour forecast window), and train_days (an optional integer for how many days of historical data to use for training).


The pipeline expects as input a merged dataframe containing both load and weather data. This dataframe is assumed to already be standardized, such as the output produced by the ISO load and weather pipeline (from goal 1).


For load data, the expected columns include ‘Name’, ‘Hour Start’, and ‘Hourly Avg Load’. For weather data, optional predictor columns include ‘temperature_2m’, ‘relativehumidity_2m’, ‘precipitation’, ‘windspeed_10m’, and ‘dewpoint_2m’. The pipeline automatically includes only the weather columns present in the dataframe.


The pipeline outputs the hourly load predictions and evaluation metrics, but also returns a dictionary with summary information from the forecasting run. The dictionary contains:
- Training target series (y_train)
- Testing target series (y_test)
- Predicted hourly load values (y_pred)
- Hourly RMSE
- Hourly MAPE
- Dataframe comparing true and predicted daily peak demand (daily_peak_comparison)


Hourly predictions and error metrics can be exported to a CSV file using the helper function save_sktime_results_to_csv(). The function takes the output dictionary from build_sktime_LGBM_model() and saves a structured results table.


The resulting CSV includes:
- Hour Start: Timestamp for the hourly reading
- actual_load: Actual load (MW)
- predicted_load: Predicted load (MW)
- error: Prediction error (actual - predicted)
- abs_error: Absolute prediction error
- percent_error: Percentage error


### GOAL 3 (Dashboard of the Results)
Input a .CSV file output of the forecasting model with the following column values: 
- Hour Start: Timestamp for the hourly reading
- actual_load: Actual load in MW
- predicted_load: Predicted load in MW
- error: Prediction error (actual - predicted)
- abs_error: Absolute prediction error
- percent_error: Percentage error
